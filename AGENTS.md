# Repository notes

- Node.js >=20; npm scripts are the source of truth. `npm run dev` builds the UI once, then watches only `src/server.ts` and its imports. After changing `src/ui/*`, run `npm run build:ui` and refresh the browser.
- `npm run bundle` compiles `src/**/*.ts(x)` to `dist/` and bundles `src/ui/dashboard.tsx` to `dist/public/`. `npm test` bundles first, then runs `node --test dist/*.test.js`; for one test file, bundle first and run e.g. `node --test dist/dashboard.test.js`. Dashboard API tests need the bundled assets. Keep the package free of an npm `build` script: npm treats it as a Git dependency preparation hook.
- `npm run test:ui` bundles first and runs `scripts/test-ui.mjs` against a temporary Fastify server/data directory. It launches Microsoft Edge on Windows, Playwright Chromium elsewhere; override with `BROWSER_CHANNEL` or install Chromium via `npx playwright install chromium`.
- `src/server.ts` loads `HOST`/`PORT`/`DATA_DIR` and starts the Fastify app in `src/app.ts`. The latter receives OTLP traces and writes per-session JSONL; `src/dashboard.ts` serves the API and bundled UI; `src/dashboard-data.ts` reconstructs session data for `src/ui/dashboard.tsx`.
- Storage defaults differ: running TS via `npm run dev` writes to `./data`, while `npm start` (compiled JS) uses `~/.local/share/opencode-langfuse-observability-local/data`. Set `DATA_DIR` explicitly to inspect the same sessions in both modes. `data/`, `node_modules/`, and non-release `dist/` outputs are ignored; the receiver and dashboard bundles under `dist/` are tracked for Git installs. Session JSONL can contain prompts and outputs.
- Generation JSONL lines after the first are deltas. Reconstruct their state **in file order before sorting by nanosecond timestamps**; usage, cost, output, and message histories are per-generation, not inherited. The plugin's reported token `total` excludes cache reads/writes; dashboard full total adds them. Keep missing metrics distinct from zero.
- Dashboard GET/HEAD routes bypass the collector's raw-request hook; other unmatched requests are logged with their body bytes. Preserve this separation when adding routes. Session detail omits raw input history until `/dashboard/api/session?session=...&item=...` is requested.
